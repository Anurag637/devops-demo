3 Docker Commands Reference

Command Syntax Function & Detailed Explanation Key Options
docker build -t docker-lab-app . Parses the Dockerfile in the current directory (.), executes build steps layer by layer, and assigns the custom tag docker-lab-app. -t (Tag), . (Build context)
docker images Queries local Docker image storage and outputs a tabular report showing repository name, tag, image ID, creation date, and size. -a (Show all layers)
docker run -d -p 8080:80 --name dockerlab docker-lab-app Instantiates an isolated container from the image. Binds host port 8080 to container port 80, runs in background, and gives it a friendly name. -d (Detached), -p (Port map), --name
docker ps Inspects active containers, displaying container ID, image, command, uptime, port bindings, and container names. -a (Show stopped containers)
docker stop dockerlab Gracefully terminates the container process by transmitting SIGTERM signal. Container name or ID
docker rm dockerlab Deletes the stopped container and frees associated filesystem storage. -f (Force removal)

4 Kubernetes (Minikube & Kubectl) Commands Reference

Command Syntax Function & Purpose Key Parameters
minikube start --driver=docker Initializes the local Kubernetes node and starts the API server, etcd, scheduler, and controller manager inside Docker. --driver=docker
kubectl apply -f deployment.yaml Declaratively creates or updates the Deployment controller managing application pod replicas. -f (File manifest)
kubectl apply -f service.yaml Creates the NodePort network abstraction exposing pods to traffic outside the cluster. -f (File manifest)
kubectl get pods Lists all pods in the current namespace along with readiness state, lifecycle status, restart count, and age. -o wide (Pod IPs & Nodes)
kubectl get deployments Outputs deployment status, including desired replicas, updated replicas, and available replicas. Current namespace
kubectl get services Displays active services, internal ClusterIPs, and exposed NodePort allocations. Cluster network table
minikube service docker-lab-service Establishes a networking tunnel to the NodePort service and launches the default web browser. --url (Only print URL)
kubectl scale deployment docker-lab-deployment --replicas=4 Modifies the target replica specification dynamically, triggering the creation of 2 additional pods. --replicas=4
kubectl delete -f <filename> Deconstructs and removes all Kubernetes resources defined within the specified YAML manifest. Graceful deletion

5 Complete Manifests Repository

1. Dockerfile Specification (lab2-project/Dockerfile):

FROM nginx:latest COPY index.html /usr/share/nginx/html/index.html EXPOSE 80 CMD ["nginx", "-g", "daemon off;"]

2. Kubernetes Deployment Manifest (lab2-project/deployment.yaml):

apiVersion: apps/v1 kind: Deployment metadata: name: docker-lab-deployment labels: app: docker-lab spec: replicas: 2 selector: matchLabels: app: docker-lab template: metadata: labels: app: docker-lab spec: containers: - name: docker-lab-container image: docker-lab-app imagePullPolicy: Never ports: - containerPort: 80

3. Kubernetes Service Manifest (lab2-project/service.yaml):

apiVersion: v1 kind: Service metadata: name: docker-lab-service spec: type: NodePort selector: app: docker-lab ports: - protocol: TCP port: 80 targetPort: 80 nodePort: 30080

7 Experiment Observations

  • Packaging Fidelity: Docker successfully encapsulated all web server dependencies and custom HTML assets into a single layer-based image.
  • Runtime Execution: The containerized Nginx instance handled HTTP requests on host port 8080 identically to a bare-metal installation.
  • Controller Reconciliation: Kubernetes Deployment successfully scheduled and maintained the desired pod replica count.
  • Service Routing: The NodePort service exposed the application on static node port 30080 and performed dynamic internal load balancing.
  • Instant Elasticity: Scaling the deployment from 2 to 4 pods was completed in approximately 11 seconds without packet loss or downtime.

8 Result

The Docker container was built and executed successfully. Kubernetes orchestrated, monitored, and scaled the application across multiple pods using declarative manifests and NodePort networking. The experiment demonstrated containerization, cluster orchestration, and automated horizontal scaling.
